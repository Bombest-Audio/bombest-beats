  <action>
Add an `e2e-android` job to the workflow. Insert it AFTER the existing `test` job and BEFORE
the `merge` job. The job must contain exactly these steps in order:

1. **Guard step** — validate secrets are non-empty BEFORE any other work. Fail fast with a
   clear error if either secret is empty (prevents silent assumeTrue skips):
   ```yaml
   - name: Validate CI credentials are configured
     run: |
       if [ -z "$CI_TEST_USERNAME" ] || [ -z "$CI_TEST_PASSWORD" ]; then
         echo "ERROR: CI_TEST_USERNAME and/or CI_TEST_PASSWORD secrets are not set."
         echo "Create a 'ci' user on beats.bom.best and add the secrets to this repo."
         exit 1
       fi
     env:
       CI_TEST_USERNAME: ${{ secrets.CI_TEST_USERNAME }}
       CI_TEST_PASSWORD: ${{ secrets.CI_TEST_PASSWORD }}
   ```

2. **Checkout** — same as existing test job:
   ```yaml
   - uses: actions/checkout@v4
     with:
       ref: refs/pull/${{ github.event.issue.number }}/head
       submodules: recursive
   ```

3. **Java setup** — same as existing test job:
   ```yaml
   - uses: actions/setup-java@v4
     with:
       distribution: temurin
       java-version: 17
   ```

4. **Gradle cache** — cache Gradle wrapper and caches to speed up repeat runs:
   ```yaml
   - uses: gradle/actions/setup-gradle@v4
     with:
       gradle-version: wrapper
       cache-read-only: false
   ```

5. **AVD cache** — cache the Android Virtual Device to avoid re-downloading the system image
   every run (saves ~3 minutes):
   ```yaml
   - name: AVD cache
     uses: actions/cache@v4
     id: avd-cache
     with:
       path: |
         ~/.android/avd/*
         ~/.android/adb*
       key: avd-pixel5-api34-arm64
   ```

6. **Create AVD** — only when cache miss (if: steps.avd-cache.outputs.cache-hit != 'true'):
   ```yaml
   - name: Create AVD
     if: steps.avd-cache.outputs.cache-hit != 'true'
     uses: reactivecircus/android-emulator-runner@v2
     with:
       api-level: 34
       target: google_apis
       arch: x86_64
       profile: pixel_5
       force-avd-creation: false
       emulator-options: -no-window -gpu swiftshader_indirect -noaudio -no-boot-anim -camera-back none
       disable-animations: true
       script: echo "AVD created"
   ```
   Note on arch: GitHub ubuntu-latest runners are x86_64 (Intel/AMD). Despite D-02 specifying
   arm64, GitHub's standard ubuntu-latest runners do NOT support arm64 Android emulation via KVM.
   ARM runners on GitHub are limited to paid/enterprise plans. Use x86_64 (which does support
   KVM on ubuntu-latest) to actually run — this is a "Claude's Discretion" area per CONTEXT.md.
   The AVD profile remains `pixel_5` and api-level remains `34` as specified in D-02.

7. **Run E2E tests** — the emulator-runner action boots the emulator and runs the script:
   ```yaml
   - name: Run E2E tests
     uses: reactivecircus/android-emulator-runner@v2
     with:
       api-level: 34
       target: google_apis
       arch: x86_64
       profile: pixel_5
       force-avd-creation: false
       emulator-options: -no-window -gpu swiftshader_indirect -noaudio -no-boot-anim -camera-back none
       disable-animations: true
       script: |
         cd android-app
         ./gradlew connectedAndroidTest --no-daemon \
           -Pandroid.testInstrumentationRunnerArguments.test.username="${{ secrets.CI_TEST_USERNAME }}" \
           -Pandroid.testInstrumentationRunnerArguments.test.password="${{ secrets.CI_TEST_PASSWORD }}"
   ```

8. **Capture logcat on failure** — capture device log after test execution, if failed:
   ```yaml
   - name: Capture logcat
     if: failure()
     run: adb logcat -d > logcat.txt
   ```

9. **Upload failure artifacts** — upload JUnit XML + logcat on failure (D-07):
   ```yaml
   - name: Upload test artifacts
     if: failure()
     uses: actions/upload-artifact@v4
     with:
       name: e2e-failure-artifacts-${{ github.run_number }}
       path: |
         android-app/build/outputs/androidTest-results/
         logcat.txt
       retention-days: 7
   ```

10. **Post PR comment summary** — always post pass/fail result (D-08). Follow the same
    `gh pr comment` pattern already used in the merge job:
    ```yaml
    - name: Post E2E result comment
      if: always()
      env:
        GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        JOB_STATUS: ${{ job.status }}
      run: |
        if [ "$JOB_STATUS" = "success" ]; then
          ICON="✅"
          MSG="E2E tests passed (Login, Playback, Playlist CRUD)"
        else
          ICON="❌"
          MSG="E2E tests FAILED — check artifacts for JUnit XML and logcat"
        fi
        gh pr comment ${{ github.event.issue.number }} --body "$ICON **E2E Android:** $MSG"
    ```

**Job-level config** (at the `e2e-android:` level, not inside steps):
```yaml
e2e-android:
  name: E2E Android tests
  needs: test
  if: |
    success() &&
    github.event.issue.pull_request != null &&
    (contains(github.event.comment.body, '🚀') || contains(github.event.comment.body, ':run-tests:') ||
     (contains(github.event.comment.body, ':run-test:') && contains(github.event.comment.body, 'android'))) &&
    (github.event.comment.author_association == 'MEMBER' || github.event.comment.author_association == 'OWNER' || github.event.comment.author_association == 'COLLABORATOR')
  runs-on: ubuntu-latest
```

**Merge job update** — change `needs: test` to `needs: [test, e2e-android]` on the merge job
so E2E failures block merge (D-10):
```yaml
merge:

  needs: [test, e2e-android]
  if: success() && needs.test.outputs.merge_requested == 'true'
```
